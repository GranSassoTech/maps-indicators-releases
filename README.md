# MAPS indicators

Territorial indicators for Italian municipalities, built from the
[MAPS Datastore](https://datastore.maps.gransassotech.org) and published here as
CSV files attached to GitHub releases.

- **The data** comes from the MAPS Datastore gold layer: the sources as published,
  reconciled to the municipalities in force on 31/12/2025.
- **The rules** (which variables, how they are combined, and why) are written by the
  analysts and recorded in the metadata file of each release.
- **Each release is a snapshot**: it records when the gold layer was read and which
  variables, with the SHA-256 of what was read.

## Indicators

Each link points to a release asset. The URLs are stable: a release is never changed
after it is published; a new reading of the data is a new release.

## Using a file

```python
import pandas as pd

url = "https://github.com/GranSassoTech/maps-indicators-releases/releases/download/<tag>/<set_id>.csv"
df = pd.read_csv(url, dtype={"territory_code": str})  # keep the leading zeros
```

Always read `territory_code` as text: ISTAT municipal codes have leading zeros
(`001001`). A code is only meaningful together with its reference geography, which
is declared in the metadata file: municipal codes change with mergers.

## What is in a release

| Asset | Content |
|---|---|
| `<set_id>.csv` | the indicators, long format: `territory_code,indicator,year,value` |
| `<set_id>.metadata.json` | reference geography; for each indicator definition, unit, source variables, rule, rationale, version; when the gold layer was read; checksums |
| `<set_id>__gold_extract.csv` | exactly what was read from the Datastore gold layer |
| `<set_id>__gold_extract_metadata.txt` | the codebook of the extract, as returned by the Datastore |

The metadata file is also committed in this repository under
`releases/<tag>/metadata.json`, so the history of every release is browsable without
downloading anything. The extracts are not committed: they are release assets, and
their checksum is in the metadata file.

Full description of the format: [docs/format.md](docs/format.md).

## Freshness

A release does not follow the Datastore automatically. A scheduled job compares each
latest release with the current gold layer and opens an issue when the data it read
has changed since. Check `gold_read.read_at` in the metadata file to know when the data
was read.
